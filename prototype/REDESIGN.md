# 界面重设计原型

针对正式前端“看着别扭”的问题，先用原型比较两个布局方向。入口为 `/redesign.html`，与 `/`、`/optimization.html` 互不影响。

**已决定并实施到正式 `frontend`**：采用 B（侧栏 + 封面）；已完成任务只出现在媒体库；设置与服务器合并为一页。正式实现保留了原型之外的既有能力（排序、刷新、Cookie 导入、待清理筛选、文件删除确认等），任务详情为右侧抽屉／手机底部弹出。

## 预览

```sh
cd /root/dev/bili/downkyi-web/prototype
npm run dev -- --port 8510 --strictPort
```

- [A · 顶栏 + 列表](http://localhost:8510/redesign.html?variant=A)：沿用现有顶部导航，改动最小，信息密度高。
- [B · 侧栏 + 封面](http://localhost:8510/redesign.html?variant=B)：左侧导航，媒体库默认封面网格，衔接优化原型 C 的媒体库方向。

右下角可切换方案和模拟断线；`&view=downloads|library|settings` 可直达页面。

## 现状问题（据 1440/390px 截图与 styles.css 统计）

| 问题 | 现状 | 原型中的处理 |
| --- | --- | --- |
| 字太小、太淡 | 基础 13px；`font-size` ≤11px 的规则有 63 处（含 8px、9px）；使用 450/550 等中文字体没有的字重 | 基础 14px，最小 12px；只用 400/500/600；次要文字对比度提高 |
| 页面框架重复 | 顶部导航 + 面包屑“工作空间 › 下载队列” + 英文眉标 DOWNLOADS + 标题 + 页脚；“已连接”出现 3 处 | 只保留导航和标题；连接状态仅在断线时用横幅提示 |
| 状态说三遍 | 状态徽标、进度条标签、筛选标签各写一次“下载中” | 状态、百分比、进度条、原因合并为一列，例如“下载中 62% · 3.4 MB/s · 剩 2 分钟” |
| 统计条信息量低 | 三张卡片显示“正在下载 1 个任务”等 | 并入标题下一行摘要 |
| 手机端表格横向溢出 | 390px 下表格列被截断 | 改为卡片行，状态在标题下方；底部标签栏导航 |
| 命名不一致 | 导航“已完成”、页面“我的媒体库”、眉标 LIBRARY；“偏好设置”和“服务器”分成两页 | 统一为 下载／媒体库／设置；服务器信息并入设置底部 |
| 详情弹窗遮挡 | 任务详情为居中模态框 | 桌面右侧抽屉，手机底部弹出；删除在抽屉内二次确认 |
| 对齐 | 服务器页内容限宽 1035px，标题栏全宽 | 统一内容区宽度 |

两个方案共用上述视觉规则，只在导航位置和媒体库默认视图上不同。

## 演示边界

- 数据为虚构样例，刷新复位；不调用 API。
- 已完成任务只出现在媒体库，不再混在下载列表中（建议，待确认）。
- 新建下载只演示第一步输入框；后续选择分 P／画质的步骤计划沿用现有流程，只换视觉。
- 播放按钮只弹提示，播放器沿用现有 ArtPlayer 实现。
- 未做深色模式。
